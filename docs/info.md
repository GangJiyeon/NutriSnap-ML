# 음식 이미지 인식 — 딥러닝 파트 

## 0. 한 줄 요약
- 역할: **"사진 한 장 → 음식 종류들과 각각의 확신도(confidence)를 뽑아주는 것"** 까지 
- 양(포션) 추정, 영양소 계산, 저장은 백엔드/DB 역할이며, 별도 부피 추정 모델은 이번 스코프에서 제외하고 추후 과제로 분리

## 1. 데이터셋 정보 (AIHub)

**링크**: https://www.aihub.or.kr/aihubdata/data/view.do?currMenu=115&topMenu=100&dataSetSn=242

| 항목 | 내용 |
|---|---|
| 카테고리 | 500여종 음식 |
| 이미지 수 | 카테고리당 약 60,000장 → 전체 약 300만 장 |
| 해상도 | 1,280×720 이상, jpg/png |
| 어노테이션 | 이미지 1장당 JSON 페어 (바운딩박스 좌표 + 클래스 라벨) |
| 영양 메타데이터 | 카테고리별 100g 기준 영양성분(칼로리/탄수화물/단백질/지방)을 1인분 기준으로 환산해서 구축됨 → 영양소 목표 화면에 쓰이는 기준값의 출처 |

**실무 유의사항**
- 회원가입 + 다운로드 승인 절차 필요 (내국인만 신청 가능), 분할 압축 파일이라 병합 필요
- 페이지에 "안심존/IRB" 안내가 붙어있는데, 헬스케어 카테고리 공통 템플릿일 가능성 높음 → 신청 페이지에서 이 데이터셋이 일반 승인 대상인지 안심존 전용인지 사전 확인 필요

**학습 전략**
- 500클래스 × 300만장 전체는 소규모 프로젝트엔 과함
- **1차 MVP**: 자주 먹는 음식 위주 50~100개 클래스, 클래스당 300~500장으로 서브셋 구성 후 파인튜닝
- 이후 사용자 로그(자주 먹는 음식, 최근 빈도) 기반으로 미인식 클래스를 점진적으로 추가

## 2. 딥러닝 파트가 전체 로직에서 하는 역할 (단계별)

| 단계 | 내용 |
|---|---|
| Step 1. 입력 수신 | 촬영/업로드된 이미지(jpg/png, 최대 10MB)를 이미지 파일 또는 URL 형태로 수신 |
| Step 2. 전처리 | 리사이즈/정규화, 저조도·저해상도 등 실패 케이스 사전 필터링 |
| Step 3. 객체 탐지+분류 | YOLOv8로 한 이미지 내 여러 음식을 각각 바운딩박스로 탐지 (단일 분류 아닌 **object detection**), 객체마다 `{class_name, confidence, bbox}` 산출, 최대 5개까지 |
| Step 4. 신뢰도 판단 | confidence ≥ 70% 자동 표시 / < 70% "확인 필요" 태그 (threshold는 설정값으로 분리) |
| Step 5. 결과 반환 | 아래 API 스펙으로 백엔드에 전달 |

```json
{
  "detections": [
    {"food_name": "흰쌀밥", "confidence": 0.96, "bbox": [x1,y1,x2,y2]},
    {"food_name": "제육볶음", "confidence": 0.91, "bbox": [x1,y1,x2,y2]},
    {"food_name": "계란찜", "confidence": 0.74, "bbox": [x1,y1,x2,y2], "needs_review": true}
  ]
}
```

**딥러닝 파트가 책임지지 않는 부분 (역할 경계 명확화)**
- 양 추정(portion size): 기본값 1.0인분 + 사용자 수동 조절 (딥러닝 범위 아님, 아래 4번 참고)
- 영양소 계산: 음식명 확정 후 백엔드가 Supabase 영양성분 테이블 조회해서 계산
- 음식명 수정/검색 자동완성: 별도 텍스트 검색 로직 (DB 쿼리, 모델 추론 아님)

## 3. 학습(Training) vs 추론(Inference) — 참고 개념

| 구분 | 시점 | 하는 일 | 어디서 |
|---|---|---|---|
| 학습(파인튜닝) | 개발 단계, 1회성 | pretrained YOLOv8(COCO로 학습됨)에 음식 데이터를 추가 학습시켜 가중치 조정 | 로컬 GPU / Colab / 클라우드 GPU |
| 추론 | 매 사용자 요청마다 | 완성된 가중치로 순전파만 수행 (새 학습 없음) | 배포된 추론 서버 |

**파인튜닝 요약**: YOLOv8의 Backbone/Neck(물체를 구분하는 저수준 능력)은 그대로 재사용하고, Head(최종 클래스 판단 부분)만 500개(또는 서브셋) 음식 클래스에 맞게 재조정. 학습률을 작게 잡아 기존 지식이 크게 망가지지 않도록 함.

```python
from ultralytics import YOLO
model = YOLO('yolov8n.pt')  # pretrained 가중치
model.train(data='food_dataset.yaml', epochs=100, imgsz=640)
```

## 4. 양 추정(Portion Size) — 스코프 및 향후 계획

| 옵션 | 방식 | 난이도 | 채택 여부 |
|---|---|---|---|
| A | 사용자 수동 조절 (기본 1.0인분, ±0.1) | 낮음 | ✅ 1차 MVP 채택 |
| B | bbox 면적 기반 근사 추천값 | 중간 | 2차 개선 후보 |
| C | Depth estimation(MiDaS 등) + 3D 부피 계산, 또는 기준 물체 스케일 보정 | 높음 (연구 수준) | ❌ 이번 스코프 제외, 별도 트랙 |

**결정 사항**: 옵션 C(진짜 딥러닝 기반 부피 추정)는 학계에서도 별도 연구분야("food volume estimation")로 다룰 만큼 무거운 주제이며, 정답 데이터(실측 그램수, depth 정보)도 별도로 구해야 함. 메인 서비스 레포와 **완전히 분리된 별도 레포/트랙**으로 진행 예정이며, 정확도가 검증되면 추론 서버에 엔드포인트를 추가하는 식으로 나중에 통합함. 현재 메인 서비스는 옵션 A로 완결된 MVP로 진행.

## 5. 서버 배포 구조 (Supabase 포함)

### 역할 분담
| 컴포넌트 | 담당 | 비고 |
|---|---|---|
| 추론 서버 (YOLOv8 서빙) | 이미지처리(딥러닝) 파트 | 별도 서버 필요, Supabase에서 직접 추론 불가 |
| 이미지 파일 저장 | Supabase Storage | 촬영 이미지 원본 |
| 유저/기록/목표 DB | Supabase Postgres | 유저 정보, 식사 기록, 목표값 |
| 영양성분 마스터 테이블 | Supabase Postgres | AIHub 메타데이터로 사전 적재 |
| 인증 | Supabase Auth | |
| 오케스트레이션 | 백엔드(Java) 또는 Supabase Edge Function | Storage 업로드 → 추론 서버 호출 → DB 저장 |

### 전체 흐름
```
[프론트] 사진 촬영/업로드
    ↓
[Supabase Storage] 원본 이미지 저장, URL 발급
    ↓
[백엔드/Edge Function] 이미지 URL을 추론 서버로 전달
    ↓
[추론 서버 (FastAPI + YOLOv8)] 탐지 결과(JSON) 반환
    ↓
[백엔드] food_name으로 Supabase Postgres 영양성분 테이블 조회
    → 1인분 기준값 × 사용자 조절값으로 최종 kcal/영양소 계산
    ↓
[Supabase Postgres] 오늘 기록으로 저장 → [프론트] 결과 표시
```

### 추론 서버 배포 옵션
- **1차**: Modal / RunPod Serverless (서버리스 GPU) — 초기 트래픽 적을 때 비용 효율적, FastAPI 코드 재사용 가능
- **트래픽 증가 시**: 자체 서버(EC2/GCP VM)로 전환
- **장기 고려**: 온디바이스(ONNX/TFLite export) — 현재 단계엔 이름

## 6. 초기 세팅 체크리스트 (딥러닝 파트 담당)
1. AIHub 데이터 다운로드 신청 및 승인 확인 (안심존 여부 체크)
2. 서브셋 구성 (50~100 클래스, 클래스당 300~500장)
3. JSON 어노테이션 → YOLO 포맷(txt) 변환 스크립트 작성
4. YOLOv8 파인튜닝 (Ultralytics)
5. 추론 결과를 API 스펙(JSON)으로 감싸는 FastAPI 서버 작성
6. requirements.txt / Dockerfile 작성 (CI/CD 연동 대비)
7. Modal 등 추론 서버 배포처 계정 세팅 및 배포 테스트
